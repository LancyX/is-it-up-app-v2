# Чи є світло — сторінка стану електропостачання

[English](README.md) · **Українська**

Невелика сторінка, зручна насамперед з телефона, яка відповідає вам і сусідам на одне питання: **чи є зараз світло?**
Вона бере датчик електропостачання з [Home Assistant](https://www.home-assistant.io/) і показує поточний стан, час останньої зміни, фактичну історію відключень, а також, за бажанням, графік відключень (через [svitlo.live](https://github.com/chaichuk/svitlo_live)) поруч із тим, що відбувалося насправді.

Зроблено для житлового комплексу під час планових і аварійних відключень. Майже повністю згенеровано за допомогою ШІ, задумувалося як забавка, але користуються щодня.

## Навіщо

Home Assistant знає, коли зникає світло, але давати сусідам доступ до нього не хочеться. Цей застосунок — публічне вікно лише для читання на один датчик: токен HA лишається на сервері, а сам HA може бути в домашній мережі чи за VPN.

## Можливості

- **Поточний стан** — є світло чи ні і скільки часу, а також остання зміна і скільки тривав попередній стан. Короткі `unavailable` у HA (наприклад, коли перезавантажується шаблонний датчик) не розбивають одне відключення на кілька.
- **Графік відключень** (необов'язково) — сьогодні й завтра сіткою годин, як у ДТЕК (кожна година поділена на півгодини), наступне відключення за графіком зі зворотним відліком і банер, коли діють аварійні відключення і графік може не виконуватися.
- **Фактична історія** — сьогодні, вчора або останні 6 год … 7 днів, з доступністю, загальним часом без світла, кількістю вимкнень і їхньою середньою тривалістю.
  - На комп'ютері: ступінчастий графік зі смугою **Графік** під ним — одразу видно, чи відключення йшли за графіком.
  - На телефоні: дві компактні смуги, **Факт** і **Графік**, на одній шкалі часу. Поверніть телефон горизонтально, щоб побачити повний графік.
  - **Усі відрізки** — розгортуваний список усіх періодів зі світлом і без за обраний час: початок – кінець, стан, тривалість.
  - Під обома смугами підписано час початку й кінця відключень, завжди парами (ніколи лише початок чи лише кінець); надто короткі для підпису відключення позначені рискою.
- **Зручно з телефона** — компактний вигляд, нічого не прив'язано до наведення мишею, дані оновлюються, щойно ви повертаєтеся у вкладку, сторінку можна додати на головний екран як застосунок.
- Світла / темна тема (за системною), українська / англійська, оновлення кожні 30 с.

## Як це працює

```
Браузер ──► nginx (фронтенд, :3033) ──/api──► FastAPI (бекенд, :8033) ──REST──► Home Assistant
```

- **Бекенд** — тонкий проксі над REST API Home Assistant (`/api/states`, `/api/history/period`, `/api/calendars`). Браузер ніколи не бачить токен HA.
- **Датчик електропостачання** — будь-який `binary_sensor` у HA зі станом `on`, коли світло є, і `off`, коли немає. Наприклад: шаблонний датчик зі стану ДБЖ «на батареї», ping-датчик пристрою, не підключеного до резервного живлення, або доступність розумної розетки.
- **Історія** береться з recorder HA, тож глибина історії — це налаштування HA `purge_keep_days` (за замовчуванням 10 днів), а не цього застосунку. Час до першого запису датчика показується як «Немає даних» і ніколи не вгадується.
- **Графік** береться з інтеграції [svitlo.live](https://github.com/chaichuk/svitlo_live) для HACS (вся Україна, зокрема Київська область / ДТЕК, у якого немає публічного API):
  - сьогодні й завтра — з її датчика стану;
  - датчик не каже, на яку дату його графік (після півночі він тримає вчорашній, доки не опублікують новий день), тому бекенд звіряє його з календарем інтеграції, де дати справжні;
  - дні, яких в інтеграції ще немає, бекенд бере напряму з API svitlo.live (джерело інтеграції для Київської області буває на добу позаду сайту);
  - минулі дні — із записаного в історії HA стану календаря, тобто графік, який діяв на той момент. Ця історія починається з моменту встановлення інтеграції.

## Налаштування

### 1. Home Assistant

1. `binary_sensor` електропостачання (див. вище).
2. Довгостроковий токен доступу: ваш профіль у HA → **Безпека** → **Довгострокові токени доступу**.
3. *(Необов'язково, для графіка)* Встановіть [svitlo.live](https://github.com/chaichuk/svitlo_live) через HACS і додайте свій регіон і чергу. Інтеграція створить сутності на кшталт `sensor.svitlo_kiivska_oblast_5_1_electricity` і `calendar.svitlo_kiivska_oblast_5_1_outages_schedule`.

### 2. Запуск у Docker

```bash
cp .env.example .env   # заповніть HA_BASE_URL, HA_TOKEN, GRID_ENTITY_ID (+ SCHEDULE_ENTITY_ID)
docker compose up -d --build
```

Відкрийте **http://localhost:3033**. nginx фронтенду проксіює `/api` на бекенд.
Якщо бекенд у Docker, а HA в локальній мережі хоста, вкажіть `http://host.docker.internal:8123` або IP HA.

### Змінні середовища

**Бекенд**

| Змінна | Опис | Приклад |
|---|---|---|
| `HA_BASE_URL` | Адреса Home Assistant | `http://192.168.1.10:8123` |
| `HA_TOKEN` | Довгостроковий токен доступу | — |
| `GRID_ENTITY_ID` | Бінарний датчик електропостачання | `binary_sensor.grid_power` |
| `SCHEDULE_ENTITY_ID` | *Необов'язково.* Датчик стану svitlo.live; вмикає картку графіка і смугу «Графік» | `sensor.svitlo_kiivska_oblast_5_1_electricity` |
| `SCHEDULE_CALENDAR_ID` | *Необов'язково.* Календар svitlo.live — щоб визначати дату графіка і для минулих днів. Якщо не задано, виводиться з `SCHEDULE_ENTITY_ID` | `calendar.svitlo_kiivska_oblast_5_1_outages_schedule` |
| `SCHEDULE_API_URL` | *Необов'язково.* API svitlo.live, з якого напряму беруться дні, яких ще немає в інтеграції (її джерело може запізнюватися). Порожнє — лише HA | `https://svitlo-proxy.svitlo-proxy.workers.dev` (за замовчуванням) |

**Фронтенд** (необов'язково, вшиваються під час збирання; передаються як build args у Docker)

| Змінна | Опис | Приклад |
|---|---|---|
| `VITE_APP_SUBTITLE` | Рядок під заголовком, наприклад адреса чи черга | `Київська область · черга 5.1` |
| `VITE_CONTACT_EMAIL` | Email у розділі «Контакт» (якщо не задано — розділ прихований) | `you@example.com` |
| `VITE_GITHUB_REPO_URL` | Посилання на репозиторій у футері | `https://github.com/...` |
| `VITE_BASE_PATH` | Базовий шлях, якщо сторінка не в корені | `/` або `/is-it-up/` |
| `VITE_API_BASE` | Шлях до API на тому ж хості | `/api` |

За reverse proxy (наприклад, Nginx Proxy Manager) задайте `VITE_BASE_PATH` і `VITE_API_BASE` відповідно до шляхів, які ви спрямовуєте на фронтенд і бекенд.

### Додати на головний екран

Відкрийте сторінку на телефоні → **Поділитися → На екран «Додому»** (iPhone) або меню браузера → **Додати на головний екран** (Android). Сторінка відкриватиметься як застосунок, без адресного рядка.

## Локальна розробка

```bash
# бекенд (потрібні HA_BASE_URL / HA_TOKEN / GRID_ENTITY_ID, наприклад `set -a; . ../.env; set +a`)
cd backend
poetry install
poetry run uvicorn app.main:app --reload --port 8000

# фронтенд (dev-сервер Vite проксіює /api на localhost:8000)
cd frontend
npm install
npm run dev
npm run build   # tsc + vite build — єдина перевірка типів
```

## API

| Ендпоінт | Опис |
|---|---|
| `GET /health` | Перевірка роботи |
| `GET /api/state` | Поточний стан датчика |
| `GET /api/last-change` | Остання зміна стану і тривалість попереднього стану (без урахування коротких `unavailable`) |
| `GET /api/history?hours=N` | Зміни стану за ковзне вікно, `N` ∈ 6, 12, 24, 48, 72, 168 |
| `GET /api/history?start=<ISO>[&end=<ISO>]` | Те саме за фіксований період (з часовим поясом; до 168 год; `end` за замовчуванням — зараз). Містить `schedule_history` — записаний графік до сьогодні, якщо графік налаштовано |
| `GET /api/schedule` | Відключення за графіком на сьогодні й завтра (за Києвом), ознака аварійних відключень і час оновлення; `{"enabled": false}`, якщо не налаштовано |

## Технології

- **Бекенд:** Python 3.11+, FastAPI, httpx, pydantic-settings, Poetry
- **Фронтенд:** React 18, Vite, TypeScript, Recharts
- **Розгортання:** Docker Compose (бекенд + фронтенд на nginx)
